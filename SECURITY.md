# Security

## Reporting a problem

Please don't open a public issue for a security problem. Use GitHub's
**Security → Report a vulnerability** (private vulnerability reporting) on
this repository instead.

## How this project handles security

| Area | Practice |
|---|---|
| Secrets | Never in Git. Real values live in `airflow/.env` (git-ignored), with a template in `airflow/.env.example`. Airflow's keys are generated by `scripts/generate_secrets.py`, and Docker Compose refuses to start without them |
| Secret scanning | gitleaks scans the **entire Git history** on every push. Past findings that were resolved by rotation are listed, with an explanation, in `.gitleaksignore`; anything new fails CI |
| API keys in logs | The Twelve Data key is sent in an HTTP header, never in a URL, so it can't appear in error messages or logs (tested) |
| Encryption at rest | Airflow encrypts stored connections and variables with a Fernet key. S3 objects use SSE-S3 |
| Dependencies | Pinned versions, audited with pip-audit in CI, and updated by Dependabot |
| Containers | Small base images, non-root users, health checks and memory limits. Images are scanned with Trivy before they are published |
| Infrastructure | Trivy checks Dockerfiles, Compose and Terraform for misconfigurations. AWS access is least privilege (`infra/terraform/iam.tf`), and the access key is never stored in Terraform state |
| Code | Ruff's security rules (Bandit) run in CI: SQL built from strings, unsafe subprocess calls, hard-coded passwords |
| Least privilege | The dashboard uses read-only database sessions and a read-only lake mount. CI workflows only get the permissions they need |

## Incident log

- **2026-11-21:** gitleaks found Airflow's internal keys (`fernet_key`, `secret_key`, `jwt_secret`) committed in `airflow/config/airflow.cfg` (2026-08-26). Impact: low, because Airflow only runs locally. All three were rotated and moved to `airflow/.env`, encryption was enabled (the Fernet key had been overridden to empty), and the old commit is recorded in `.gitleaksignore`.
- **2026-11-21:** the API key could appear in logs, because an HTTP error message includes the request URL, which contained `apikey=`. Fixed by header authentication; the one affected local log was redacted.
- **2026-11-21:** pip-audit found 5 advisories in `urllib3` 2.7.0 and `certifi` 2026.7.22. Upgraded to 2.8.0 and 2026.10.18.
- **2026-11-21:** the Trivy image scan in CD blocked publishing the Airflow image: the `apache/airflow:3.1.0` base had fixable CRITICAL vulnerabilities in Airflow itself and in bundled libraries (PyJWT, Authlib, GitPython and others). Upgraded the base image to 3.3.2 and aligned `requirements.txt` with the versions it ships.
